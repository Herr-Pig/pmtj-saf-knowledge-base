# 文献批次工作约定

资料按一批统一选取、核验和审核。保留现有完整索引audit、图片权利登记、owner approval及内容哈希机制，不增加逐条确认步骤。

1. 后续收集在独立工作分支（如`codex/literature-batch-YYYYMMDD`）或忽略的`.build/reading-inbox/<batch>/`完成。合法全文、SI、原图下载及提取文本只作为本地核验缓存；未核实的线索不直接写成已证结论。
2. 以DOI及官方身份去重。每条记录列书目、实际膜堆、页码/图号、阅读状态、作者直接证据、作者解释、本库推断和限制。无需每条文献向所有者重问。
3. 选定正文、元数据和图像后，完成本地构建、链接、图文与版权核对，再一次性生成完整变更清单及SHA-256清单。普通排版修正纳入同批，不逐个请求批准。
4. 图片区分本库原创、论文原图、作者示意面板及许可未核线索。论文中的示意图仍是第三方论文图，不能登记成本库原创。撤下的资源保留本地源文件，不进入MkDocs发布目录。
5. 所有者审核最终批次清单及其哈希后，才按该决定更新owner-approval和图片批准字段。候选选择、版权许可核实与最终文件哈希批准分别记录；旧批准不能替代新版本。
6. 现有Git提交/推送钩子及Pages审核继续执行。当前规则不能提交未批准的本地图时，保留已完成工作及暂存内容，不禁用钩子、不伪造授权，也不借元数据工具绕过检查。
7. main与线上网站在批次通过前保持不变。发布仍需明确的手动工作流和匹配提交SHA；不建立自动同步或自动部署。

批次清单可保存在忽略的本地`.build/<batch>/`，最终给所有者一份清单与一个manifest摘要即可。需要补读的少数条目随批次标记，不为追求数量补造全文、图号或许可。
